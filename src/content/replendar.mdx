## 문제 해결

<CaseStudy number="01" title="프론트 팀이 같은 흐름으로 개발하도록 만들기">

### 문제

여러 프론트엔드 개발자가 동시에 화면을 구현하고 백엔드와 API를 연결하려면 일정, 코드 품질, 변경된 명세를 함께 관리할 기준이 필요했습니다.

### 판단

팀장 역할을 화면 개발에만 한정하지 않고 프로젝트 초기 세팅, 개발 일정 조율, Pull Request 리뷰와 협업 문서 관리까지 이어지는 흐름으로 설계했습니다.

### 구현

프론트엔드 프로젝트를 세팅하고 작업 일정을 관리했습니다. 병합 전 Pull Request의 코드를 리뷰했으며, 노션 데이터베이스에 API 명세와 파트·전체 회의 기록을 남겨 프론트엔드와 백엔드가 같은 정보를 참고하도록 했습니다.

### 결과와 근거

서비스 결과물과 함께 코드 리뷰가 반영된 공개 저장소, API 명세와 회의 문서를 남겼습니다.

</CaseStudy>

<CaseStudy number="02" title="로그인부터 개인화된 과제 관리 화면까지 연결하기">

### 문제

사용자가 자신의 과제와 일정을 관리하려면 인증 흐름과 서버 데이터, 여러 화면 상태가 끊기지 않고 이어져야 했습니다.

### 판단

카카오 로그인과 API 연동을 중심에 두고, 사용자가 과제의 진행 상태와 마감일을 쉽게 확인하도록 화면과 인터랙션을 구성했습니다.

### 구현

React 기반 화면에 카카오 소셜 로그인과 백엔드 API를 연결했습니다. 지연 로딩을 적용하고 스크롤에 따라 이동하는 사이드바, 반응형 애니메이션과 전역 상태 기반 배경 테마 변경을 구현했습니다.

### 결과와 근거

과제 등록·공유, 캘린더, 내 정보와 테마 설정으로 이어지는 화면을 구현했습니다. 구현 화면과 정보 구조도는 아래 결과 자료에서 확인할 수 있습니다. 지연 로딩의 개선율은 측정 자료가 없어 수치로 제시하지 않습니다.

</CaseStudy>

<CaseStudy number="03" title="프론트 결과물을 직접 배포하기">

### 문제

팀이 만든 프론트엔드 결과물을 브라우저에서 확인하고 시연할 수 있는 배포 환경이 필요했습니다.

### 구현

GitHub Pages를 이용해 프론트엔드를 배포하고 서비스 도메인에 연결했습니다.

### 결과와 근거

프로젝트 완료 시점에 웹 결과물을 배포했습니다. 현재 백엔드 서버 이용 기간이 끝난 상태이므로 포트폴리오에는 당시 구현 화면과 공개 저장소를 근거로 제공합니다.

</CaseStudy>

## 협업과 리더십

UMC 7기 Replendar의 프론트 팀장을 맡아 초기 세팅과 개발 일정을 조율하고, Pull Request 병합 전 리뷰어로 참여했습니다. 화면 구현과 함께 API 명세, 파트 회의와 전체 회의 기록을 관리해 팀의 결정과 작업 상황을 공유했습니다.
