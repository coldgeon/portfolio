## 문제 해결

<CaseStudy number="01" title="토큰 보관·갱신·인증 복원을 하나의 흐름으로">

**문제** · 액세스 토큰을 메모리에 보관하면 새로고침 후 인증이 사라졌습니다.

**조치** · 메모리 액세스 토큰 + HttpOnly 리프레시 쿠키 + 재발급·RTR 흐름을 구현했습니다.

**결과** · 액세스 토큰을 로컬스토리지에 남기지 않으면서 새로고침 후 인증을 복원했습니다.

</CaseStudy>

<CaseStudy number="02" title="관리자 화면을 기존 배포 환경에 통합">

**문제** · 새 관리자 기능을 기존 API·온프레미스 운영 환경에 연결해야 했습니다.

**조치** · Vite 화면을 Spring Boot API와 연동하고 프론트 빌드를 백엔드에 포함했습니다.

**결과** · 기존 Nginx·백엔드 배포 흐름에서 관리자 기능을 제공했습니다.

</CaseStudy>

<CaseStudy number="03" title="기존 알림 식별자 보호">

**문제** · device_id·FCM token의 저장·처리 흐름에 보호가 필요했습니다.

**조치** · RSA·AES 하이브리드 암호화를 적용했습니다.

**범위** · 관리자 로그인 토큰과 구분한 기존 알림 서비스 유지보수 작업입니다.

</CaseStudy>
